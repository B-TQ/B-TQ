# A practice in questions and making

The profile is a short editorial portfolio: identity, one featured work, three complementary works, then the questions connecting them. The main proposition stays in selectable Markdown text. Images are a nameplate and an original comparison sheet, not a replacement for the document.

## Visual language

Warm off-white and near-black, broad type, narrow rules, generous empty space. Brackets turn the identity mark into a frame for investigation; the featured image groups A/B/C/D under one shared requirement set. Equal rectangles are condition labels, not measurements. D has an inverse treatment to identify the minimal-reminder comparison, not to claim a winner.

Light and dark assets have separate palettes. All SVGs use only local geometry and system font fallbacks; there are no scripts, remote fonts, filters, tracking pixels or external asset services. GitHub-supported picture markup declares both color schemes. The live profile HTML wraps these pictures in GitHub's themed-picture component; manual GitHub theme switching remains a separate visual check.

## Curatorial choice

Judgment OS leads because it connects a concrete Python toolkit with a careful question about AI guidance. Public source, tests, releases and evidence limitations support the description. The profile does not claim the experimental Skill improves agents generally.

Microchem Desktop demonstrates a different medium: chemical ideas made manipulable. Its public repository distributes software and documentation; it does not expose the complete application source and does not grant unrestricted use. The profile preserves those boundaries.

dsh-wallpaper shows interface experimentation. Windows App Relocation Diagnosis shows evidence-led troubleshooting. Forked repositories are omitted from the authored-work selection. Only already-public projects are described.

## Activity and maintenance

GitHub's native contribution calendar and repository timestamps provide live activity. No duplicated metrics, scheduled commits, external stats cards or custom Actions are needed. Releases links remain current without putting a stale version number in the profile.

Edit README.md for copy and links. Edit both theme variants for an asset change. Keep the same viewBox and hierarchy across variants, provide useful alt text, and check at narrow widths. Update this selection when a different public work earns the lead.
